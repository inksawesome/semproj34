# Random-Walk OTP System

> **Second-Factor Authentication Module — SemProj Face-Recognition Login System**
> 
> A TOTP-style (RFC 6238) OTP system where the HMAC-SHA1 core is replaced by a **random walk on a graph** as the pseudo-random generation function.

## Algorithm Deep-Dive

### Step 1 — Time Counter
```
T = floor(unix_time / time_step)
```
Default `time_step = 30s` (configurable). Identical assumption to RFC 6238 (NTP-synced clocks).

### Step 2 — Walk Seed Derivation
```
seed_bytes = HMAC-SHA256(K, T_as_8_byte_big_endian)
```
This is the cryptographic anchor: the seed is only computable by parties that know `K`. The graph `G` itself is **not secret** — it is a shared public structure (like the hash function in TOTP is public).

### Step 3 — Random Walk on Graph
1. **Start node**: `seed_bytes[:8]` → uint64 → `mod N` (N = number of nodes)
2. **Step PRNG**: `random.Random(seed_bytes)` — seeded with the full 32-byte HMAC output
3. Take `S` steps, choosing a random neighbour at each step
4. Record the sequence of visited node IDs → `path = [n₀, n₁, …, nₛ]`

The graph `G` is a deterministic Watts–Strogatz-style small-world graph (base circular lattice + 30% rewiring), generated from a fixed public seed. Same graph on every machine.

### Step 4 — Path Encoding & Truncation
```
encoded = concat(big_endian_uint16(node) for node in path)
offset  = encoded[-1] & 0x0F               # RFC 4226 dynamic truncation
code    = int.from_bytes(encoded[offset:offset+4], 'big') & 0x7FFFFFFF
otp     = str(code % 10^digits).zfill(digits)
```

### Step 5 — Validation Window
Server checks OTPs for `T-1, T, T+1` to absorb clock drift, exactly like standard TOTP.

## The Seed-Swap Point

> **This section documents exactly where fractal-derived seeds will replace the random secret K.**

Currently, `K` is a 32-byte cryptographically random string generated by `generate_secret()`. It is **the only input** that the rest of the system depends on — and it enters the algorithm at **exactly one location**:

```python
# walk_otp.py — line ~100
def _derive_walk_seed(secret_k: bytes, counter: int) -> bytes:
    counter_bytes = struct.pack(">Q", counter)
    return hmac.new(secret_k, counter_bytes, hashlib.sha256).digest()
```

### How to swap in a fractal-derived seed

In the fractal-integrated version, your fractal geometry module will produce a deterministic byte string from the user's face template (e.g., fractal dimension parameters → SHAKE-256 → 32 bytes). To wire it in:

**Option A — drop-in replacement (recommended):**
```python
# fractal_seed.py (your teammate's module)
def derive_seed_from_face(face_embedding: np.ndarray, user_params: dict) -> bytes:
    """Returns 32 bytes derived from fractal geometry of the face template."""
    # ... fractal computation ...
    return shake_256_output  # 32 bytes

# In enrollment / OTP generation:
K = derive_seed_from_face(face_embedding, params)  # instead of generate_secret()
otp, _ = generate_otp(K, config=otp_cfg)          # unchanged
```

**Option B — HMAC fusion (if K stays separate):**
```python
# Combine fractal bytes with the stored K via HMAC:
fractal_bytes = derive_seed_from_face(face_embedding, params)
combined_k = hmac.new(stored_k, fractal_bytes, hashlib.sha256).digest()
otp, _ = generate_otp(combined_k, config=otp_cfg)
```

**Interface contract**: the function `generate_otp(secret_k: bytes, ...)` accepts **any 16–64 byte sequence** as `secret_k`. The random-walk logic is completely unchanged. Nothing else in the module needs modification.

## Quick Start

### 1. Install dependencies
```bash
pip install fastapi uvicorn cryptography python-dotenv pytest httpx qrcode pillow
```

### 2. Configure environment
```bash
cp .env.example .env
# Generate a master key:
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
# Paste the output as WALK_OTP_MASTER_KEY in .env
```

### 3. Start the server
```bash
cd otp_system
uvicorn server.app:app --reload --port 8000
```

### 4. Enroll a device (client side)
```bash
cd otp_system
python client/client_cli.py enroll --server http://localhost:8000 --device-id my_laptop
```

### 5. Generate OTPs (no network needed)
```bash
python client/client_cli.py generate
# Or one-shot:
python client/client_cli.py generate --once
```

### 6. Verify against server
```bash
python client/client_cli.py verify --server http://localhost:8000
```

## API Reference

### `POST /enroll`
```json
{ "device_id": "optional-string", "user_label": "optional-string" }
```
Returns `{ device_id, secret_b32, qr_payload, graph_config, otp_config, message }`.  
**K is returned exactly once.** Store immediately.

### `POST /verify`
```json
{ "device_id": "string", "otp": "123456" }
```
Returns `{ valid: bool, device_id, message }`.  
Rate-limited to 10 attempts per 60s per device.

### `DELETE /devices/{device_id}`
De-enroll a device. Admin use only.

### `GET /devices`
List enrolled device IDs.

## Security Notes

| Property | Implementation |
|----------|---------------|
| K never re-transmitted | Returned only once at `/enroll`; never in logs |
| K encrypted at rest | Fernet (AES-128-CBC + HMAC) via `WALK_OTP_MASTER_KEY` |
| Replay prevention | Server tracks `last_used_counter` per device |
| Brute-force protection | Rate limit: 10 attempts / 60s / device |
| Clock drift tolerance | ±1 time-step window (±30s with default config) |
| OTP comparison | `hmac.compare_digest` (constant-time, no timing oracle) |
| Secret entropy | 256-bit CSPRNG (`secrets.token_bytes(32)`) |
| Anomaly logging | `_log_failure()` stub in `server/app.py` — wire to ELK/Splunk |
