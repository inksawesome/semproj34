ABSTRACT
Conventional authentication systems that rely on static passwords or single-factor One-Time Passwords
(OTPs) remain vulnerable to credential theft, replay attacks, and biometric template compromise. This
project proposes a multi-factor authentication system that combines facial biometrics enhanced with
fractal-geometry-based feature extraction and template protection, together with a novel second-factor
OTP mechanism generated via random walks on a graph rather than conventional HMAC-based schemes.
During enrolment, a user's facial embedding is combined with fractal-dimension features (derived using
box-counting / iterated-function-system techniques) and passed through a fractal transform to produce
a non-invertible, cancelable protected template stored in the database. During login, the same pipeline
is repeated, an AI-based anti-spoofing (liveness) check is performed, and, upon a successful match, a
second-factor OTP is required. This OTP is generated independently on both the server and a trusted
client device from a shared secret and a synchronised time-step, using a deterministic random walk over
a shared graph structure whose traversal path is encoded and truncated into a 6-digit code, analogous
to RFC 6238 TOTP but with the walk replacing HMAC as the core pseudo-random function. This report
presents the literature review, problem statement, objectives, proposed system, methodology, software
requirements, system architecture and UML design for the project, along with the current
implementation status of the random-walk OTP engine and the face-capture/biometric pipeline.
Keywords: Fractal Geometry, Biometric Authentication, Template Protection, Graph Random Walk, One-
Time Password, Multi-Factor Authentication, Liveness Detection, Chaotic Systems.
1. INTRODUCTION
Digital identity verification increasingly relies on multi-factor authentication (MFA) to counter the well-
known weaknesses of static passwords. Biometric modalities such as face recognition offer convenience
but introduce their own risks: unlike a password, a compromised biometric template cannot simply be
reset, and stored raw feature vectors are subject to reconstruction and cross-matching attacks.
Meanwhile, the dominant second-factor mechanism in use today, the Time-based One-Time Password
(TOTP), depends on HMAC-based pseudo-random generation from a shared secret and time counter.
This project investigates whether concepts from fractal geometry, specifically fractal-dimension feature
extraction and chaotic/fractal transforms, can be used both to strengthen facial-template protection
and to seed an alternative OTP-generation mechanism based on random walks over a graph structure.
The two originally separate project ideas (fractal-geometry-based authentication and graph-random-
walk OTP generation) have been merged into a single, coherent authentication pipeline, where the
fractal module supplies the entropy/transform layer and the graph-walk module supplies the second-
factor mechanism.
2. PROBLEM STATEMENT
Existing single-factor and even many multi-factor authentication systems suffer from three related
weaknesses: (i) biometric templates are frequently stored with insufficient protection, exposing users to
irrevocable identity compromise if a database is breached; (ii) conventional OTP mechanisms rely on a
small, well-studied set of pseudo-random constructions (primarily HMAC-based TOTP/HOTP), making
them a predictable and heavily-targeted attack surface; and (iii) face-based login alone is susceptible to
presentation attacks (photos, replayed video, masks) unless combined with robust liveness detection
and a genuinely independent second factor. There is a need for an authentication design that protects
biometric templates using a non-invertible transform, and that generates second-factor codes using an
alternative, less conventional pseudo-random mechanism while remaining synchronisable between
server and client without constant network communication.
3. OBJECTIVES
• To design a facial authentication pipeline that combines standard face-recognition embeddings
with fractal-geometry-derived features (e.g., fractal dimension via box-counting) for enrolment
and login.
• To design and implement a fractal-transform-based protected template mechanism that stores
a non-invertible, cancelable representation of the enrolled biometric rather than the raw
embedding.
• To design and implement an AI-based anti-spoofing (liveness detection) stage that prevents
presentation attacks (photos, replay video, masks) from passing the login check.
• To design and implement a second-factor OTP-generation mechanism based on random walks
over a graph, seeded by a shared secret and a synchronised time-step, such that server and
client can independently compute matching OTPs without a network round-trip for generation.
• To integrate the biometric-authentication pipeline and the random-walk OTP engine into a
single end-to-end login flow, and evaluate its correctness, refresh behaviour, and resistance to
basic replay/expiry conditions.
4. SCOPE OF THE PROJECT
The scope of this project (Review-1 stage) covers: (a) a working random-walk-based OTP generation and
verification engine (server + client, TOTP-style independent generation), which is currently implemented
and demonstrable; (b) a face-capture and biometric-embedding pipeline, currently under active
development and testing; (c) the design (architecture, methodology, UML) of the fractal-feature-
extraction and fractal-transform/template-protection module, which is planned for the next
implementation phase; and (d) the design of the anti-spoofing and second-factor integration flow.
Large-scale performance benchmarking, formal security-proofs of the fractal transform, and production-
grade deployment (e.g., HSM-backed key storage) are out of scope for this stage and are noted as future
work.
5. PROPOSED SYSTEM
The proposed system consists of two integrated stages, Registration and Login, described below.
Registration: Email → Email Verification → Face Capture → Face + Fractal Feature Extraction → Fractal
Transform (per-user key) → Create Protected Template → Database. On first successful login, the device
is additionally enrolled as a trusted device by exchanging a shared OTP secret (K) over the already-
authenticated session.
Login: Webcam → Face Capture → Face + Fractal Feature Extraction → Apply the same Fractal
Transform → Compare against the stored Protected Template, in parallel with AI Anti-Spoofing (liveness)
→ if REAL and MATCH, proceed to the Second Factor (OTP) stage; otherwise reject → Random-Walk OTP
is computed independently on the server and on the trusted client device from the shared secret and
the current time-step → OTP verified → Session granted.
This design gives fractal geometry two functional roles: (1) an auxiliary texture/feature signal alongside
the face embedding, and (2) the non-invertible transform used to create the protected template, which
is the mechanism that makes the stored template cancelable and resistant to reconstruction/cross-
matching attacks.

6.1 FINDINGS IN LITERATURE SURVEY
Across Topic 1, chaotic maps and fractal-dimension features are consistently shown to provide high
sensitivity to initial conditions and strong randomness properties, useful both for image-level encryption
and for biometric feature representation, but no reviewed work combines fractal features with formal
biometric template-protection schemes such as fuzzy vaults - this is the specific gap the project
addresses. Across Topic 2, existing OTP literature is dominated by conventional HMAC-based
TOTP/HOTP constructions and standard cryptographic primitives (SHA-512, AES-256); graph-theoretic
and random-graph-traversal ideas exist and have been applied to image encryption, but have not been
applied to OTP generation - the second gap this project addresses. Across Topic 3, CNN-based anti-
spoofing and multi-factor architectures are well studied and provide a strong basis for the liveness-
detection stage of the proposed login flow, confirming that this component of the design is feasible
using established techniques.
7. METHODOLOGY
• Enrolment: capture face image, extract face embedding and fractal-dimension features (box-
counting method on facial texture), and pass the combined feature vector through a fractal
transform seeded by a per-user key to produce a protected, non-invertible template stored in
the database.
• Liveness detection: apply an AI-based anti-spoofing model to the captured frame(s) in parallel
with face matching, classifying the input as REAL or SPOOF before allowing progression to the
second factor.
• Trusted-device enrolment: on first successful login, generate a random shared secret K and
exchange it once with the client device over the authenticated session (analogous to
TOTP/Google-Authenticator pairing).
• OTP generation (Model B - independent generation): both server and client compute a time-
step T = floor(current_time / time_step); derive a seed from K and T; run a deterministic random
walk of fixed length over a shared graph structure from a seed-determined start node; encode
the visited-node path into a byte string; truncate/hash it into a 6-digit numeric OTP, refreshed
every 30-60 seconds and invalidated on time-step rollover.
• Verification: the server compares the OTP submitted by the user against the OTP(s) expected for
T-1, T, T+1 (to tolerate minor clock drift), rejects reused/expired codes, and grants the session
only if both the biometric match and OTP verification succeed.

8. SOFTWARE REQUIREMENTS: Functional and Non-Functional
Requirements
Functional Requirements
• The system shall allow a user to register with an email address, verify it, and capture a face
image for enrolment.
• The system shall extract face and fractal-dimension features and store only a protected
(transformed) template, never the raw embedding.
• The system shall perform liveness detection on every login attempt before allowing a biometric
match to succeed.
• The system shall generate a 6-digit OTP on the server and independently on the trusted client
device, refreshed every 30-60 seconds.
• The system shall verify the submitted OTP against the expected value(s) within the tolerance
window and reject expired/reused codes.
Non-Functional Requirements
• Security: the shared OTP secret (K) must never be transmitted or logged after the initial
enrolment exchange; all transport must use TLS.
• Performance: OTP generation and biometric matching should complete within a few seconds to
remain usable at login time.
• Usability: the login flow (face capture, liveness check, OTP entry) should require minimal user
action beyond looking at the camera and reading a 6-digit code.
• Reliability: the system should tolerate small clock-drift between server and client without falsely
rejecting valid OTPs.

11. SUMMARY
This report presents the design of a merged authentication system that uses fractal geometry both for
facial-feature extraction/template protection and, together with random walks on a graph, for second-
factor OTP generation. The literature review across three focus areas (fractal/chaotic biometric
protection, graph-based OTP generation, and face liveness/MFA) confirms the individual techniques are
well established while the specific combination proposed here is not directly covered in existing work,
motivating the project's approach. At this review stage, the random-walk OTP engine is implemented
and demonstrable, the biometric pipeline is implemented and under test, and the fractal-transform
module is designed and scheduled for the next implementation phase, in line with the expected 50%
implementation checkpoint for Review-1.
