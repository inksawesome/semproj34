# Integration Guide: Component 1 (Face Anti-Spoofing)

This document lists the new files and modifications required to integrate **Component 1 (Spatial + Frequency-Domain Analysis)** into the main project repository. 

Our implementation intercepts the authentication flow immediately after face detection, executing a passive liveness check (using a dual-branch Spatial + Fast Fourier Transform neural network) to reject printed photos and screen replays before generating an ArcFace embedding[cite: 1, 4, 5, 22].

---

## 1. New Files to Send to the Team

Send the following three Python files and one model checkpoint to your teammates. They should be placed in the root directory of the project alongside `app.py`.

### A. `frequency_transform.py`
**Context:** Implements the preprocessing logic for the Frequency Branch[cite: 22]. It converts the cropped RGB face into a 2D Fast Fourier Transform (FFT) log-magnitude spectrum, which exposes hidden digital artifacts like screen moiré patterns and print halftone dots that the naked eye misses[cite: 22].

### B. `spatial_frequency_model.py`
**Context:** Defines the PyTorch architecture for the passive liveness detector[cite: 22]. It contains:
* A ResNet-18 spatial encoder for the RGB face[cite: 22].
* A ResNet-18 frequency encoder for the FFT spectrum[cite: 22].
* A feature fusion block that concatenates the 512-D vectors from both branches into a final dense classifier[cite: 22].

### C. `fas_checker.py`
**Context:** The operational gatekeeper script. It provides the `check_liveness()` function, which combines the deep neural network forward pass with dynamic physical heuristics (like Laplacian texture sharpness, YCrCb chromatic dispersion, and high-frequency energy ratio bounds) to compute the final spoof/real decision. It explicitly crops the inner 60% of the face to ignore white shirts and background glare.

### D. `fas_spatial_freq.pth`
**Context:** The baseline PyTorch model weights file for the `SpatialFrequencyFAS` architecture. 

*(Note: Ensure your teammates know how to generate this file locally if you don't send it, using: `python -c "import torch; from spatial_frequency_model import SpatialFrequencyFAS; torch.save(SpatialFrequencyFAS(pretrained=True).state_dict(), 'fas_spatial_freq.pth')" `).*

## 2. Existing Files to Update / Replace

Your teammate must update the following existing project files to wire the new component into the pipeline.

### A. `app.py`
**Context:** The main Streamlit application script requires updates to route the webcam frame through the FAS module.
* **Import addition:** Needs `from fas_checker import check_liveness`.
* **Execution change:** Inside `biometric_capture()`, immediately following `detect_and_crop_face(image_rgb)`, the script must call `check_liveness(face_crop)`[cite: 4, 23]. If it returns `is_real == False`, `app.py` must halt execution and display a rejection message, bypassing `get_embedding()` entirely[cite: 4, 5, 23].

### B. `mediapipe_face.py`
**Context:** The legacy `mediapipe.python.solutions.face_mesh` API has been deprecated in modern environments.
* **Change:** The file was rewritten to utilize the modern **MediaPipe Tasks `FaceLandmarker` API**. It now automatically downloads `face_landmarker.task` and performs a robust 20% margin facial crop without crashing on import.

### C. `requirements.txt`
**Context:** Deep learning dependencies are now required.
* **Change:** Append `torch` and `torchvision` to the list of requirements to support the ResNet-18 architecture.

## 3. Project Architecture Handoff

When handing off to the team members building **Component 2 (Active Liveness)** and **Component 4 (Explainable AI)**, inform them that `fas_checker.py` currently outputs a binary decision and a confidence score. They will need to hook their Grad-CAM visualizations and randomized blink/smile challenge functions into this same stage of `app.py` to achieve the final fused decision outlined in the project brief[cite: 22].
