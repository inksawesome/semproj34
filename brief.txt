Proposed Face Anti-Spoofing Module
Implementation Brief
Spatial + Frequency Analysis • Active + Passive Liveness • Explainable AI
1. Objective
The existing system performs face recognition/authentication. The proposed addition is a Face Anti-Spoofing (FAS) module that operates before face recognition.
The purpose is to prevent an attacker from gaining access by presenting printed photographs, photos displayed on phones/tablets, replayed videos, screen-based attacks, masks or other physical presentation attacks, AI-generated/deepfake faces, face-swap/re-enactment videos, and other unseen spoofing attacks.
The system combines:
1. Spatial + frequency-domain analysis
2. Passive + active liveness detection
3. Explainable AI (XAI)
The final architecture should be designed to improve robustness against attacks that were not present in the training set.
2. Overall Architecture
Camera → Face Detection → Face Alignment/Cropping
→ Spatial Analysis + Frequency Analysis
→ Feature Fusion
→ Passive FAS Score
→ Active Liveness Check
→ Decision Fusion
→ REAL / SPOOF
If REAL → existing Face Recognition → Identity Verification
If SPOOF → Reject Authentication + Explain the decision
3. Component 1 — Spatial + Frequency-Domain Analysis
A conventional FAS system may primarily learn spatial features such as skin texture, facial structure, reflections, edges and image artifacts. Spoofing can also introduce subtle frequency-domain artifacts, including high-frequency patterns, compression characteristics and display/printing artifacts.
The proposed approach therefore uses two branches:
RGB Face → Spatial Encoder
RGB Face → Frequency Transform (FFT/DWT) → Frequency Encoder
→ Feature Fusion → REAL/SPOOF
The spatial branch can use ResNet-18, ResNet-50, EfficientNet-B0 or MobileNetV3. For an initial implementation, ResNet-18 or EfficientNet-B0 is recommended.
4. Frequency Branch
Start with a 2D Fast Fourier Transform (FFT):
Face image → FFT → Frequency representation → Frequency encoder
The Fourier representation can be considered in terms of amplitude and phase. Frequency information can expose characteristics that are less obvious in normal RGB space.
A second option is Discrete Wavelet Transform (DWT), which decomposes the image into:
LL — low-frequency approximation
LH — horizontal/high-frequency information
HL — vertical/high-frequency information
HH — diagonal/high-frequency information
Recommended development path: implement FFT first because it is simpler, then optionally compare FFT with DWT.
5. Feature Fusion
The spatial and frequency branches produce feature vectors.
Example:
Spatial feature = 512 dimensions
Frequency feature = 512 dimensions
Concatenate:
[Spatial features | Frequency features]
Then pass the combined representation through a fully connected layer, dropout and classifier.
Start with simple concatenation. An attention-based fusion mechanism can be investigated later if required.
6. Component 2 — Passive Liveness Detection
Passive liveness means the user does not have to perform a specific action. The system observes the face and determines whether it appears genuine using visual and temporal cues.
The spatial-frequency model becomes the primary passive FAS detector.
For multiple frames:
Frame 1 → spoof probability
Frame 2 → spoof probability
...
Frame N → spoof probability
Aggregate predictions across a short sequence instead of trusting one frame.
7. Component 3 — Active Liveness Detection
Add a second security layer by giving the user a randomized challenge.
Possible challenges:
Turn head left
Turn head right
Blink twice
Smile
Look upward
The challenge should be randomized rather than always using the same action.
Flow:
Random challenge → capture short video → verify requested action → challenge pass/fail
Active liveness should be treated as an additional security signal, not as the sole spoof detector, because sophisticated replay/deepfake attacks may reproduce actions.
8. Active Challenge Verification
Blink detection can use facial landmarks and Eye Aspect Ratio (EAR). A significant temporary reduction in EAR followed by recovery can indicate a blink.
Head movement can be verified using facial landmarks/head-pose estimation through yaw, pitch and roll.
Example:
Initial yaw = 2°
Instruction = “Turn left”
Observed yaw = -25°
→ Challenge passed
Smile can be verified using mouth landmarks or a facial-expression model.
The challenge verifier should output a Boolean result and, preferably, a confidence score.
9. Component 4 — Explainable AI
The system should not simply output “SPOOF”. It should provide evidence for the decision.
Example:
SPOOF DETECTED
Confidence: 94%
Evidence:
Abnormal facial texture
High-frequency anomaly
Active challenge failed
The explainability layer should be separate from the main classification decision.
10. Grad-CAM
Grad-CAM is a practical first explainability technique for the spatial CNN. It generates a heatmap showing which image regions influenced the prediction.
The heatmap can help identify whether the model focuses on meaningful regions such as eyes, mouth, cheeks, forehead or screen boundaries.
Grad-CAM should primarily be used to interpret and debug the model, not to determine the final classification.
11. Frequency-Domain Explainability
Because the proposed model explicitly uses frequency information, the system can additionally visualize the frequency representation used by the model.
Possible output:
Spatial explanation → face + Grad-CAM heatmap
Frequency explanation → frequency spectrum / high-frequency emphasis
This can make the explanation more closely aligned with the proposed architecture.
12. Final Explainable Output
Example UI:
FACE AUTHENTICATION
Anti-Spoof Result: SPOOF
Confidence: 96.2%
Evidence:
✓ Spatial anomaly
✓ Frequency anomaly
✗ Active challenge

For a genuine user:

Proceeding to face recognition...
13. Complete Authentication Flow
1. Capture live camera video.
2. Detect the face.
3. Crop, align, resize and normalize the face.
4. Run passive FAS using spatial + frequency branches.
5. Generate a random active challenge when appropriate.
6. Capture and verify the requested action.
7. Fuse passive, frequency and active-liveness signals.
8. If SPOOF → reject authentication.
9. If REAL → pass the frame to the existing face-recognition module.
10. Generate an explanation containing classification, confidence, Grad-CAM/frequency evidence and active-challenge status.
14. Training Strategy
Do not build the entire system simultaneously.
Phase 1 — Baseline:
RGB → ResNet/EfficientNet → REAL/SPOOF
Measure accuracy, precision, recall, F1, APCER, BPCER and ACER.
Phase 2 — Frequency:
RGB → Spatial encoder
RGB → FFT → Frequency encoder
→ Fusion → Classifier
Compare spatial-only versus spatial + frequency.
Phase 3 — Active Liveness:
Add randomized challenge and landmark/head-pose/blink verification.
Compare passive-only versus passive + active.
Phase 4 — Explainability:
Add Grad-CAM and frequency visualization.
Phase 5 — Unseen-Attack Evaluation:
Test on attack types, devices, lighting conditions or manipulation methods not used during training.

Possible datasets to investigate include:

CASIA-FASD
Replay-Attack

WMCA

Dataset choice should depend on whether the project targets physical attacks, digital attacks, or both.
A strong evaluation strategy is to train/validate on one set of attacks and hold out different attacks, devices or domains for testing.
16. Evaluation Metrics
Do not report only accuracy.
APCER — Attack Presentation Classification Error Rate. Measures attacks incorrectly classified as genuine. Lower is better.
BPCER — Bona Fide Presentation Classification Error Rate. Measures genuine users incorrectly rejected. Lower is better.
ACER — Average Classification Error Rate:
ACER = (APCER + BPCER) / 2
Also report:
Precision
Recall
F1-score
ROC-AUC
FAR
FRR
Inference time
FPS
APCER is especially important because the security objective is to reject attacks.

18. What Should Be Claimed as Novel?
Do not claim that FFT-based FAS, active liveness, or Grad-CAM individually are new. These are already represented in existing research.
A stronger project contribution is:
“An integrated anti-spoofing architecture combining spatial-frequency representation, randomized active liveness, and explainable decision analysis, with particular emphasis on generalization to unseen attacks.”
The novelty should be established through a focused literature review before the final research claim is written.
19. Recommended Technical Stack
Programming: Python
Deep learning: PyTorch (recommended for experimentation) or TensorFlow/Keras
Computer vision: OpenCV
Face detection: MediaPipe, RetinaFace, YOLO-face or MTCNN
Face landmarks: MediaPipe Face Mesh or an equivalent landmark model
Spatial model: ResNet-18 initially
Frequency transformation: FFT initially; DWT as an optional comparison
Explainability: Grad-CAM
Active liveness: Eye Aspect Ratio for blink; facial landmarks/head pose for head movement; landmark geometry or expression model for smile

23. Core Research Question
Can an integrated spatial-frequency and active-passive liveness framework improve the robustness and interpretability of face authentication against both known and unseen spoofing attacks?
The project should focus its experiments on cross-domain generalization, unseen attacks, explainability, deepfake robustness and real-time deployment rather than simply maximizing accuracy on a single dataset.
References / Literature Starting Points
IEEE Access (2025): Survey on face anti-spoofing, including CNNs, domain generalization, Transformers, CLIP/VLMs and explainability.
FSDA / Fourier-based FAS research: frequency-domain representations for improving generalization to unseen spoof domains.
Recent wavelet-based FAS research: frequency refinement for robustness to noise and low-quality inputs.
Recent explainable FAS research: Grad-CAM and facial-region analysis for spoof explanations.
WACV 2025: Frequency-domain explainability for face recognition, useful as a conceptual basis for frequency explanations.
